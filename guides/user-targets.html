User Targets

Targets can be set for users over a given period to improve sales performance, for example, sell 1,000 cases across outlets this month to hit a bonus.

Setting a new target

Follow these steps to view and set a target for a user from the portal.

  1. Open the user's page

    Go to http://<DomainName>.bizom.in/users/view/user_id, for example, http://stagingtraining.bizom.in/users/view/17.

  2. Click "New Target"

  3. Enter the SKU to set the target for

  4. Review existing targets

    Click Manage Targets, then View, to see every target already uploaded for this user.

  5. Click a target to see its full details

    Opens Id, User, Start/End date, Amount, TLSD, Total Calls, LPSC, Drop Size, % Productivity and New Call for that specific target.

Target Achievement

Once orders are placed and fulfilled, targets are considered achieved. Achievement against a target can be reviewed per user, for any date range.

  1. Open the user's page

    Same URL as above: http://<DomainName>.bizom.in/users/view/UserId.

  2. Select a date range

  3. Click Update

    The user's achievement for that date range is displayed.

Bulk upload via MDM

Setting targets for many users and SKUs at once? Use the User Targets MDM.

Key fields for the User Targets MDM
FieldNotes
user_idMandatory. Must exist and be active in the system.
skunit_idMandatory. The SKU the target applies to, must exist and be active.
quantityTarget quantity, in cases. Mandatory when skunit_id is set.
startdate / enddateBoth mandatory, in YYYY-MM-DD format. The start date can't fall after the end date, and the two can't overlap with an existing target for the same user and SKU.
is_activeBoolean. New inactive-target entries aren't allowed.
dropsize, totalcalls, percentproductivecallOptional productivity metrics tied to the target period.
uniqueskuperaccounts, uniqueoutlettargetOptional reach-based target metrics.

Not supported: amount-based targets, amount is accepted in the sheet but there's no functional support for it yet.

Common validation errorsOverlapping date ranges for the same user + SKU, an inactive SKU or user, and a quantity entered without a matching skunit_id are the most frequent upload failures, the row-level error will name the exact user/SKU/date conflict.
